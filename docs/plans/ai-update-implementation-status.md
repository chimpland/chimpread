# AI library update: implementation status

October 23, 2026. Source audit of the working checkout during implementation. This records a first usable slice, not completion of the [backlog](ai-update-backlog.md) or satisfaction of every [release gate](ai-update-release-gates.md). Those planning documents remain specifications; their acceptance criteria are not test results.

The current implementation adds local whole-library keyword search, deterministic or optional AI metadata organization suggestions with explicit review, optional provider answers over retrieved passages, and a one-way Obsidian exporter. It is not an autonomous semantic librarian. It does not infer or merge intellectual works, editions, contradictions, or replication relationships.

## Concrete resource boundaries

These are code limits, not measured peak-memory guarantees.

- Research index: 128 MiB input PDF limit, 500 pages per PDF, 30,000 characters per extracted page, 2 MiB extracted text per document. SQLite database capped at approximately 128 MiB; rollback journal can temporarily add another database-sized allocation on disk. SQLite cache target is 4 MiB with mmap disabled. Temporary PDF snapshots add disk use. PDFKit can allocate more than these text limits before extraction returns.
- Retrieval: first 1,024 query characters and 16 alphanumeric terms; OR keyword matching; API result count capped at 50, MCP at 20, GUI passage results at five; snippets capped at 2,000 characters. No similarity or inference guarantee follows from a match.
- Proposal state: 32 MiB JSON file limit checked before reading and writing; at most 10,000 pending proposals, 20,000 dismissals, 10,000 transactions, and 10,000 legacy digests; apply batches at most 500 operations; new applications stop when canonical receipt count reaches 10,000. Metadata suggestion runs support at most 10,000 records. Limits reject work rather than silently prune history. No promise of indefinite undo after a history limit is reached.
- Legacy organization input: 4 MiB file limit. Supported operations are reversible organization values, never deletion, arbitrary filenames, or edition replacement.
- AI: one active request per app process; question at most 4,000 UTF-8 bytes; at most eight evidence excerpts, each at most 2,000 characters (exact displayed text) and title at most 300 characters; combined prompt at most 64,000 UTF-8 bytes; requested output allowance 1,800 tokens for answers or 4,096 for metadata organization; response transport at most 256 KiB and usable answer at most 32,000 UTF-8 bytes; 120-second request/resource timeout; no automatic retries. Provider-specific token semantics can differ. These limits do not impose a guaranteed dollar bill ceiling.
- Ollama requests specify an 8,192-token context and `keep_alive: 0`; successful unload and actual memory use are not verified. A loopback endpoint does not prove the chosen model runs locally.
- MCP: incremental framing rejects request lines over 1 MiB; page output capped at 24,000 characters per call; notes bounded by a scan of 100 pages/2,000 annotations plus output pagination. These are per-request bounds, not an aggregate library-disclosure budget. Existing known-ID reads are governed by the broad content permission, not archive visibility.
- Obsidian exporter: at most 10,000 supplied annotations, approximately 2 MiB raw content budget, and 4 MiB formatted/existing-note limit. The exporter does not read whole PDFs; UI annotation collection has separate behavior. It does not promise bounded PDFKit allocations for arbitrarily complex documents.

## Build and operational audit

`build.sh` compiles an explicit source/test list, links native frameworks plus SQLite/Security, writes a temporary executable, replaces the executable in `build/chimpread.app`, copies resources, and ad-hoc signs that local bundle. It does not itself run tests, deploy a release, notarize, or publish anything. A successful build therefore establishes compilation and local packaging only. Native export UI wiring was being completed during this audit; confirm its source is included in the final explicit build list and perform the integration check before declaring the connector delivered.

The new optional `researchTransactionIDs` field decodes in existing version-1 libraries. Current saves preserve receipts. Older app binaries do not understand or preserve those receipts and do not honor the new advisory write lock. Do not run old and new binaries against the same library; backward decoding compatibility does not imply transaction-safe downgrade. Locks protect cooperating implementations, not arbitrary processes running as the same user.

Atomic writes and receipt recovery cover the designed application interruption points. They are not a claim of fsync-level power-loss durability. The proposal journal remains local; undo after a sync can correctly reject changed fields. It does not reconstruct another device's proposal history.

## Release blockers and follow-up

1. Record the integrated build/regression/MCP/memory results against the final source state; perform native UI, cancellation, keyboard, and accessibility checks.
2. Complete authenticated-provider checks before claiming live model interoperability. Initial Obsidian source fields now escape Markdown/HTML; the separate connector update owns its later export and editor-concurrency checks.
3. Do not advertise “verified answers,” automatic paper connections, semantic organization, edition deduplication, full-library scientific synthesis, or completed backlog acceptance. Current keyword matches, metadata-based collection suggestions, and citation-number checks do not establish those capabilities.
4. Document global MCP access honestly. Per-client grants, immediate in-flight revocation, bounded total run work, and asynchronous cancellation remain future work.
5. Exercise disk-full/corrupt-source/hanging-PDF cases and representative hardware workloads before making public memory or recovery guarantees. The extractor is a background queue in the app process, not a killable isolated subprocess.
6. Complete source-supported scientific evaluations, organization precision/recall, richer evidence/provenance, identity review, spending reservations, and new-artifact sync as separate backlog slices.

This status intentionally distinguishes implementation progress from the broader product promise. The whole-library-first direction remains the goal; the present slice supplies local discovery and a safe review mechanism on which deeper organization can be built.
